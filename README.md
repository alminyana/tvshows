# tvShows

Personal SPA to catalog and manage favorite TV shows: create/edit shows with a cover image, genres, seasons, rating and opinion; browse them in a list with multiple views and filters; see a detail page; and explore a dashboard with stats. Three access roles (public read-only Viewer, User, and Admin).

The backend is **Supabase** (Postgres + Auth + Storage + RLS). After the Phase 2 migration the app no longer uses IndexedDB: all persistence goes through Supabase.

## Stack

- **React 19** + **Vite** + **TypeScript**
- **React Router v6**
- **React Hook Form** + **Zod** (forms and validation)
- **Recharts** (dashboard charts)
- **SASS** scoped per component + CSS variables for theming
- **Supabase** (`@supabase/supabase-js` v2): Postgres, Auth, Storage, RLS
- **Vitest** + **React Testing Library**
- **pnpm** as the package manager (only `pnpm-lock.yaml` is committed)

## Requirements

- Node 22+
- pnpm 9.15 (pinned via `packageManager` in `package.json`)
- A Supabase project (EU region) with its keys

pnpm install

## Supabase

The CLI ships as a dev dependency; invoke it with `pnpm supabase <command>`.

- **Migrations** are versioned in `supabase/migrations/`. No schema changes by hand without reflecting them in a migration.
- Apply migrations to the linked project: `pnpm supabase db push`.
- **Types** are generated by the CLI into `src/types/database.types.ts` (`pnpm supabase gen types typescript --linked`).
- Helper **scripts** (data migration, anti-pause heartbeat) are documented in [`scripts/README.md`](scripts/README.md).
- **Heartbeat:** a scheduled GitHub Action (`.github/workflows/heartbeat.yml`, every ~3 days) writes to the `heartbeat` table to avoid the free-tier pausing on inactivity. It needs the repo secrets `VITE_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.

## Architecture

```
src/
  components/{ui,features,layout}/   # ui = presentational; features = with logic
  pages/                             # one per route
  hooks/                             # `use` prefix
  services/                          # the only path to persistence (Supabase impl + mappers)
  context/                           # AuthContext, ThemeContext
  lib/                               # Supabase singleton client
  types/  utils/  constants/
  styles/                            # reset, variables, mixins, themes/
supabase/migrations/                 # versioned schema + RLS + Storage
scripts/                             # Node utilities (data migration, heartbeat)
```

Design invariants:

- **The services layer is the only path to persistence.** Components and hooks never talk to Supabase directly; they go through `seriesService`, `usersService`, `imageService`, `genresService`. Every method returns `Promise<T>`. A **mappers** layer (`services/mappers/`) translates snake_case (DB) ↔ camelCase (app) so column names never leak to consumers.
- **Three roles** — *Viewer* (no login, read-only, default; resolved with public-read RLS on `series`), *User* (logged in but read-only), and *Admin* (CRUD on all shows + user management). Creating, editing and deleting shows is admin-only, both in the UI (`src/utils/permissions.ts`) and in the routes (`/series/new` and `/series/:id/edit` are guarded with `roles={['admin']}`). Session and roles are handled by **Supabase Auth** + a `profiles` table; routes are guarded by `ProtectedRoute`.
- **Theming** uses CSS variables with semantic tokens (`--color-bg`, `--color-primary`, …) selected via `[data-theme][data-mode]`: 4 themes × light/dark = 8 combinations. `ThemeContext` owns `{ theme, mode }`; the first render respects `prefers-color-scheme`. UI preferences (theme, view mode) are the only thing persisted in `localStorage`.
- **Cover images** live in the `covers` Storage bucket. The DB stores the **path**, not the binary; `imageService` resolves `path → URL` for the `<img>`.
- **Genres** are a single catalog in the `genres` table, with an N:M relation to `series` through the `series_genres` join table.
- **UI copy in Spanish**, centralized in `src/constants` to prepare for i18n. Variables, functions, and components in English.
